## Plugin shape and loading

The package default-exports `{ id: "opencode-beads", setup }`, the object `Plugin.define` returns; no runtime import is needed. `setup` returns a cleanup that aborts the event subscription.

OpenCode resolves a package plugin as `<name>/server`, then `<name>`. The package exports both specifiers to `src/plugin.ts`, and the package smoke test checks both. A configured local plugin must be a directory with an `index` or `server` entry file; a file path is rejected, relative paths resolve from the config file's directory, and a missing entry is skipped without a log line. Files in `.opencode/plugins/` load automatically.

## Boundary inventory

| Boundary | Supported contract and decision |
| --- | --- |
| Location | `ctx.location.directory` scopes every `bd` process. The host's `process.cwd()` is the user's home directory, so `bd` is always spawned with an explicit `cwd`. |
| Options | `ctx.options` carries the object form `{ "package": ..., "options": {...} }`. The plugin reads `luna`, `autoMigrate`, and `stealth` as strict booleans, and `refreshAfterIdleMinutes` and `taskAgentSteps` as non-negative numbers; invalid values fall back to defaults. |
| Agents | `ctx.agent.transform(editor => editor.update(id, fn))`. The editor has no `add`; `update` on an unknown ID creates the agent from OpenCode defaults, including the default permission ruleset. User `agents` configuration overrides plugin fields one by one, and the editor does not list configuration-only agents, so V1 collision warnings were dropped. The host appends a `browser` deny rule. |
| Agent permissions and steps | `Agent.Info.permissions` is an ordered rule list where the last match wins, and agent rules apply after base rules. Shell resources match whole command text with `*` and `?`, and compound commands are checked per command. The task agents append `ask` rules for `git commit *`, `git push *`, `bd dolt push *`, `bd dolt pull *`, and `bd sync *`, each paired with a global-options form such as `git * push *`. `tests/agents.test.ts` checks the resulting decisions with a copy of the 2.0.27 matcher (a trailing ` *` also matches nothing). A non-interactive run rejects these (`permission.rejected`). `steps` caps a worker invocation (default 100). |
| Agent lookup | `ctx.agent.get({ agentID })` returns `Agent.Info` with `mode`; it is safe to call inside a session hook (about 1 ms). Subagents are excluded from context; lookup failures fail open. |
| Context | `ctx.session.hook("context", event => event.system.push({ type: "text", text }))` runs before every agent-loop model request with `sessionID` and `agent`. Pushed parts reach the model, are not stored in history, and survive compaction. Subagents launched through the `subagent` tool run in child sessions with their own `sessionID` and also pass through this hook. Compaction requests use the separate `compaction` hook; the plugin registers it only to add Beads state-preservation guidance for sessions that had Beads context. While prime is attached, bd's full-profile and Codex `AGENTS.md` blocks in the system text are replaced with a pointer (request only). |
| Events | `ctx.event.subscribe({ signal })` yields `{ type, data }`. The plugin uses `session.compaction.ended` (invalidate cached prime) and `session.deleted` (drop session state), both with `data.sessionID`. A manual compaction emitted `session.compaction.ended`, not `session.compacted`. |
| Diagnostics | V2 has no plugin log API. Rate-limited `console.warn` lines prefixed `[opencode-beads]` are emitted, and their failures never affect requests. |
| Shell | There is no `$` helper in V2. Bounded process lifecycle control uses `Bun.spawn(["bd", "prime"], { cwd, ... })` through a shared `runBd` runner with timeout and process-group cleanup; `node:child_process` also works in the host. |

## Commands and skills

V2 plugin commands are executable (`execute` calls `ctx.session.prompt`). Separately, native [Markdown and JSON commands](https://opencode.ai/v2/docs/commands/) support prompt templates, description metadata and argument substitution. The [full integration analysis](claude-code-integration-analysis.md) pins current source and records the remaining minimum-host qualification; command retirement was not forced by an absence of V2 prompt templates. Plugin-provided skills need a `path`. The vendored `/beads:*` templates were retired instead of ported (`opencode-beads-2zs.4`). OpenCode V2 discovers the canonical `.agents/skills/beads` skill installed by `bd init` natively, and users can load it with `@beads`.
