## Lifecycle and alternatives

N1 writes synchronously inside the typed operation and returns its evidenced status before ordinary continuation. The compaction hook is reference-only: it carries acknowledged references and known gaps, with no pending-write state, new permission wait or recursive same-session prompt. `session.prompt`/`session.compact` admission is not completion evidence. Meaningful earlier checkpoints protect against compaction; crash-final-write guarantees are unsupported.

**Concrete permission contract (F2):** S05 `Tool.snapshot` filters on `tool.options?.permission ?? name`; set `options.permission: "shell"` for direct and code-mode inventory filtering. S15 `configured` resolves `agent ?? session.agent`; pass the actual invocation `context.agent`, sessionID and source message/call ID. Assert `action: "shell"` with canonical resource text for the fixed argv operation, preserving selective write denials. S15 saves an "always" reply only when `request.save?.length`; use `save: []`, never a new broad `bd *` grant. Expected “always” acceptance is one-call, so explain repeat prompts. Existing shell `bd *` project grants can authorize equivalent typed operations, subject to configured denies evaluated first. S18 shell parsing gives `bd` a one-token prefix, explaining that existing grant scope. Qualify these outcomes without broadening permissions. Plain rejection must propagate.

S18 shell preparation resolves cwd, scans target directories, calls `access.authorizeExternal`, then asserts shell resources. The added S18 file-access source shows `external_directory` resources and scope. Plugin assertion alone does not reproduce this path. Bind the narrow adapter to the actual resolved location/workspace, check routing/redirect/symlink/environment effects and guard hold before spawn and after approval. Assert equivalent external-directory restrictions with invocation identity and no broad saved grant where needed; if target or equivalence cannot be established, refuse before store access. Never add a permissive custom action or silently use N0. Qualification covers shell-denied/read-only agents, changed invocation identity, allow/ask/deny, cancelled approval and external targets; no new generic permission manager.

S13 command names are schema strings and map keys. The released app parser splits the slash name only on whitespace, and submit finds the exact registered name, so `oc-beads:ready` is source-supported through that path. Installed slash discovery/dispatch, collision/rebuild preservation and resource paths remain acceptance checks. Preserve-existing behavior must survive reload; an initial list check alone is insufficient. Report a concrete namespace or lifecycle incompatibility before enabling the affected registration.

Load registers package-owned surfaces and bounded, location-scoped hooks, then subscribes to notifications with explicit cleanup. First eligible request resolves actual session scope and authority, provides guarded workflow and targeted recovery. During work, the model selects task checkpoints or reusable-memory operations; the typed tool validates and asserts permission, runs supported CLI arguments and returns an honest acknowledgement. Relevant context becomes stale only on known changes, with targeted reads for external uncertainty. Tool hooks provide focused cues and child-result feedback, not autonomous semantic writes. Compaction carries acknowledged references and known gaps only; it neither writes nor requests another same-session turn. Completion/failure events update diagnostics without forcing continuation. Reload/deletion abort observers and clear ephemeral state; later recovery reads durable records.

Compared with Claude hook shell scripts, typed tool identity and success/error payloads allow precise feedback without parsing arbitrary shell text; mutable context hooks can scope guidance to the actual session/request; native inbox/child results avoid a separate completion poller; package registrations can remove discovery entries with package lifecycle. These are evidenced integration affordances, not proof of better model judgment or durability than Claude. Claude's richer resource guidance remains valuable.

Historically evaluated CLI-based N0 with native hooks has lower implementation/compatibility cost but weaker acknowledgement and refresh precision. Blanket automatic extraction from tool output is rejected because transport success does not establish reusable meaning and introduces privacy/duplication errors. An end-event-triggered “save everything” loop is rejected because it races shutdown/compaction, can undo deliberate stop and recursively trigger itself. Custom compaction replacement or auxiliary `generate` could extract semantics, but adds model cost/failure/authorization and provider-state consequences; it is not the recommended base. No extractor seam needs implementation now; a later demonstrated need can be evaluated separately.
