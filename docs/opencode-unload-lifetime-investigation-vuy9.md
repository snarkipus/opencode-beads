## Owning scopes and ordering

The normal whole-location reload path has this order:

1. The global Session executor acquires the selected location graph through `Instance.provide`, running the location-scoped runner inside that borrowed layer. A `Reloaded` result releases that invocation and recursively acquires the selected replacement. This borrow owns the graph lifetime; an HTTP registry request has its own shorter borrow. [Session execution:95–107](https://github.com/anomalyco/opencode/blob/ba546ec1598a70db2570e9c6258028d955ba8f58/packages/core/src/session/execution.ts#L95-L107), [instance selection:8–18](https://github.com/anomalyco/opencode/blob/ba546ec1598a70db2570e9c6258028d955ba8f58/packages/core/src/effect/app-node-builder.ts#L8-L18).
2. Reload enumerates loaded locations and invalidates their routing entries. `location-services.ts` explicitly preserves running steps' borrowed graphs until a boundary. Its logical shutdown closes permissions, forms and RPC and emits `location.shutdown`; it does **not** call `Plugin.close` there. Replacement builds are then booted. Returning from reload establishes replacement builds, not completion of every old graph's teardown. [Location map:20–37](https://github.com/anomalyco/opencode/blob/ba546ec1598a70db2570e9c6258028d955ba8f58/packages/core/src/location-service-map.ts#L20-L37), [invalidation:63–79](https://github.com/anomalyco/opencode/blob/ba546ec1598a70db2570e9c6258028d955ba8f58/packages/core/src/location-services.ts#L63-L79), [logical shutdown:43–59](https://github.com/anomalyco/opencode/blob/ba546ec1598a70db2570e9c6258028d955ba8f58/packages/core/src/location-lifecycle.ts#L43-L59).
3. The runner checks `lifecycle.isClosed()` at `advanceToStep`. If reload happens after that check while request context preparation is pending, the current step can finish using its captured services. Once that step returns, the next boundary closes its model transport and returns `Reloaded`. No location-closed recheck is inserted between the awaited context hook and construction of the current provider request. [Runner:69–82](https://github.com/anomalyco/opencode/blob/ba546ec1598a70db2570e9c6258028d955ba8f58/packages/core/src/session/runner/llm.ts#L69-L82), [current request:228–243](https://github.com/anomalyco/opencode/blob/ba546ec1598a70db2570e9c6258028d955ba8f58/packages/core/src/session/runner/llm.ts#L228-L243).
4. After old borrowers release, closing that graph reaches the plugin supervisor's `registry.close` finalizer. Core then closes the plugin root/activation scopes. The Promise adapter's actual setup-disposer invocation is `Effect.acquireRelease(...plugin.setup(context2), cleanup => ...cleanup())`, at **`packages/plugin/src/promise/adapter.ts:619–622`**. This is when the product cleanup is invoked, rather than when another graph's registry changes. [Supervisor:135–138](https://github.com/anomalyco/opencode/blob/ba546ec1598a70db2570e9c6258028d955ba8f58/packages/core/src/plugin/supervisor.ts#L135-L138), [plugin scope close:238–248](https://github.com/anomalyco/opencode/blob/ba546ec1598a70db2570e9c6258028d955ba8f58/packages/core/src/plugin.ts#L238-L248), [setup cleanup:619–622](https://github.com/anomalyco/opencode/blob/ba546ec1598a70db2570e9c6258028d955ba8f58/packages/plugin/src/promise/adapter.ts#L619-L622).

Promise hook registrations are attached to the setup scope using the captured runtime at adapter lines 243–251. Session callbacks are wrapped as awaited Promises at lines 591–595. The callback itself does not acquire an additional plugin-generation lease: the Session's graph borrow keeps its owning services alive. Hook disposal removes an entry from the map used by **future triggers**. `PluginHooks.trigger` already iterates an array reference; replacing the map's array does not retract callbacks already selected or cancel a Promise already running. The public `SessionContext` declaration provides no unload AbortSignal. [Hook registration/trigger:69–94](https://github.com/anomalyco/opencode/blob/ba546ec1598a70db2570e9c6258028d955ba8f58/packages/core/src/plugin/hooks.ts#L69-L94), [Promise session declarations:25–37](https://github.com/anomalyco/opencode/blob/ba546ec1598a70db2570e9c6258028d955ba8f58/packages/plugin/src/promise/session.ts#L25-L37).

**In-place plugin removal is a different ordering within the same graph.** A watched config change publishes `Config.Event.Updated`; the existing supervisor reruns activation. For a healthy removed/replaced plugin suffix, `Plugin.activate` deletes the old active slot, **awaits `Scope.close` of its activation**, loads remaining/replacement definitions, assigns the new public inventory, then publishes `Plugin.Event.Updated`. It does not first detach a location graph and substitute another registry. Normal plugin removal/replacement must also be distinguished from the separate transform-failure recovery path, which can schedule teardown asynchronously. [Normal activation:125–175](https://github.com/anomalyco/opencode/blob/ba546ec1598a70db2570e9c6258028d955ba8f58/packages/core/src/plugin.ts#L125-L175), [config-change activation:223–244](https://github.com/anomalyco/opencode/blob/ba546ec1598a70db2570e9c6258028d955ba8f58/packages/core/src/plugin/supervisor.ts#L223-L244).

## Adapter responsibility and the selected guarantee

The accepted adapter's cleanup immediately sets its abort flag and disposes the context controller before awaiting registration/observer cleanup: `src/host.ts:172–190`. Controller disposal marks it disposed and aborts cached loads; `systemFor` checks disposal/abort again after its awaited load (`src/context.ts:173–175,187–191`). The host context hook checks the plugin abort flag after awaiting `systemFor`, before appending context (`src/host.ts:357–358`). Thus the accepted source already suppresses late injection **when actual setup cleanup has occurred before completion**. This is source evidence, not a new runtime pass or proof covering every race.

The public Promise-plugin documentation says OpenCode awaits cleanup on actual unload/replacement. The public **location.reload** description separately says running sessions continue with fresh services at the next step boundary. Those are compatible contracts. The old probe substituted absence from a replacement graph's registry for completion of the old setup scope's cleanup. The unconditional interpretation “no old output after location reload returns or the new registry omits the package” exceeds the public/native 2.1.1 reload behavior. The narrower actual-unload guarantee remains a reasonable separate acceptance target and still needs its correctly owned observation. [Plugin cleanup docs:29–38](https://github.com/anomalyco/opencode/blob/ba546ec1598a70db2570e9c6258028d955ba8f58/packages/plugin/src/README.md#L29-L38), [public reload contract:51–59](https://github.com/anomalyco/opencode/blob/ba546ec1598a70db2570e9c6258028d955ba8f58/packages/protocol/src/groups/location.ts#L51-L59).

There is no demonstrated failure of the adapter's abort checks after its cleanup, no demonstrated upstream violation of the documented reload boundary, and no basis for a downstream drain/supervisor/replay engine. The original stronger selected acceptance result remains **failed**, not retroactively passing under this explanation.

## Managed service and practical consequence

The user's default-service correction is confirmed. `server-connection.ts:21–48` selects an explicit endpoint for `--server`, a private server for `--standalone` or disabled service, and otherwise resolves a managed service with `Service.ensure`. Its managed command is the same CLI `serve --service` (`service-config.ts:133–145`). Private standalone starts `serve --stdio --port 0`, with stdin acting as its process ownership lease.

Foreground and managed modes converge on the same server `start(...)` in `server-process.ts:100–160`, and the same `AppNodeBuilder`/`buildLocationServiceMap` Core graph. Managed mode changes discovery/registration, persistent process ownership, saved server settings/environment and startup cwd; explicit session location therefore matters. It does **not** select a different plugin cleanup or current-step reload rule. This conclusion is source-backed; it is not a claim that managed startup itself was live-qualified. [Connection selection](https://github.com/anomalyco/opencode/blob/ba546ec1598a70db2570e9c6258028d955ba8f58/packages/cli/src/services/server-connection.ts#L21-L48), [common server launch](https://github.com/anomalyco/opencode/blob/ba546ec1598a70db2570e9c6258028d955ba8f58/packages/cli/src/server-process.ts#L100-L160).

For real managed-service users, closing or reopening a client does not imply server/plugin teardown. Config reload can make new requests use new registries while a current step finishes with its old context. Native watched plugin changes can instead unload/rebuild plugin scopes in the existing location. Restarting the server is process teardown with separate execution recovery semantics, and deliberate Stop is explicit cancellation. None of those operations is interchangeable with a registry query or hot location reload. No operator action was performed here.
