# Proposal

## Why

The historical comparison established setup-lifecycle parity, not the complete Claude marketplace experience. The selected redesign aims for coherent native discovery, task execution, recovery and durable learning; Matt's reported note/memory gap motivates evaluation but does not establish host or model causality.

## What Changes

- Adopt the complete marketplace-main integration as the behavioral reference, resolved for this evaluation to `4a67d0d0288c1b4ee23e17fc896f47616931ba2d`. Preserve the separate 73-file v1.3.1 inventory and characterize installed/release/current differences.
- Deliver N1: an eleven-operation typed daily-loop namespace, awaited context/tool hooks, reference-only compaction guidance, observational events, package-owned `oc-beads` skill/resources and `oc-beads:<command>` commands. Supply all selected surfaces from npm; bd remains the external executable/database owner.
- Adapt core daily workflows, expose all advanced guidance on demand without enabling automation, make supported admin workflows accessible under normal permissions, and replace obsolete/host-specific/broken content with documented native equivalents. The inventory maps every member.
- **BREAKING, opt-in beta/next only:** target OpenCode `>=2.1.1 <2.2` and replace mandatory one-bead/command-count delegation with scope-bounded continuation. Exact assignments stop; authorized batches/goals may continue with atomic claims and per-bead validation. Stable consumers do not silently migrate. No package/version/tag changes are made here.
- Preserve restricted-agent visibility, invocation identity, narrow saved approvals, location restrictions, holds, cancellation and honest persistence failures. An unqualified N1 guarantee blocks the affected path; N0 is a historical alternative, not a silent degraded default.
- Extend the existing scheduled pattern with advisory marketplace-main source comparison and immutable review links. Completed comparisons succeed despite ordinary main development; they do not gate product CI, adoption or release. Incomplete comparison is unavailable evidence, distinct from no change, without gating product/release checks. Tagged CLI compatibility remains separate. Human-reviewed baseline advancement only; no GitHub issue creation or issue-write permission.
- Apply the [2.1.1 contract delta](../../../docs/opencode-2.1.1-contract-delta.md): adopt native replay fields and retained-history semantics without replacing host compaction. Admit only the 2.1 patch line (`>=2.1.1 <2.2`); exact 2.1.1 is the unexecuted live target, not a proven compatibility result. Future patches are candidates for normal source/acceptance checks, not automatically tested versions.
- Retain code-mode composition with the owner-accepted OpenCode 2.1.1 nested plain-decline continuation limitation: the rejected operation never executes or receives success acknowledgement, but whole-step termination is not promised. Later operations retain their own permissions; explicit Stop/Cancel qualification remains required. Preserve the failed stronger case as historical evidence. The broader investigation is now reconciled into tasks 7.1–7.3 for source preparation; remaining qualification stays paused for parent review and separate dispatch. This is not authority for an upstream patch or implementation.
- Qualify source contracts, disposable deterministic fixtures and live/model outcomes separately, including fresh-session recovery, discovery and authorized continuation. Architecture and tool-call counts are not behavioral proof.

- Replace the withheld five-tool surface with `beads.find/get/edges/memories/recall/claim/note/update/close/create/remember`, declared structured results and supported fixed argv. Surface actual host-derived actors to typed and shell workflows; use request capability-aware guidance. Native shell is direct-only, never callable inside execute. Add a planned CODE_MODE resource (16 resources plus ADR, 17 links), retaining all 30 human commands and full prime pending measurement.
