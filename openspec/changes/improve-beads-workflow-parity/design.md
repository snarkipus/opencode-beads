## Context

See [proposal](proposal.md), [owner decisions](owner-decisions.md), [full corpus analysis](../../../docs/claude-code-integration-analysis.md) and [native call-site assessment](../../../docs/opencode-native-parity-assessment.md). The operative host baseline is now 2.1.1; see the [contract delta](../../../docs/opencode-2.1.1-contract-delta.md). The following 2.0.32 pin remains historical, not relabeled. Released OpenCode 2.0.32 is `843a6c514e606b436a7fe713422ace0a93ad3d61`; development `8f7b012…` is not that release.

Current `src/host.ts` registers context/compaction hooks and agents; `src/context.ts` caches prime by session/audience; `src/guidance.ts` mandates one-bead workers and command-count delegation. There are no packaged commands or rich skill. These are concrete seams for an opt-in redesign, not reasons to retain the current restrictions.

## Goals / Non-Goals

**Goals:** complete native workflow access, semantic continuity and authority-preserving execution, with small adapters over the existing runner and host. Separate discovery, execution acknowledgement and behavioral qualification.

**Non-goals:** a new datastore, generic manager, write queue, transcript harvester, background scheduler, identity service, telemetry stack, backup project or automatic migration. No product work occurs in this planning reconciliation.

## Decisions

### 2. Native delivery and complete corpus

Use D01 command transforms and D04 skill transforms in `src/host.ts`, with small `src/workflows.ts` definitions and npm assets under `assets/oc-beads/`. Register skill `oc-beads` with a real installed path. Ship its SKILL.md, all 15 adapted resources and ADR rationale, with explicit links to all 16 supporting files (host auto-listing truncates at ten); register every inventory command as `oc-beads:<stem>` (29 entries), plus a read-only `oc-beads:status` diagnostic. Replacements retain discoverable entry names but explain current supported equivalents. All commands submit scoped normal prompts, forwarding user text, attachments and delivery; none execute shell interpolation directly.

The released command schema uses a string name and the registry is keyed by that name (S13); colon names are source-supported. UI slash discovery/invocation is an installed-host acceptance check, not a completed observation. A parser rejecting the namespace is a concrete stop gate requiring a documented equivalent, not an automatic rename.

All advanced resources remain available on demand (agent beads, molecules/chemistry, gates, worktrees, static references); availability does not enable automation, nested workers or store setup. Admin commands use ordinary permissioned CLI workflows with current help and explicit requested scope. `quickstart` becomes onboarding; `template` replaces stale template syntax with supported template/formula discovery; `version` reports installed versions; `init` is human-directed setup guidance. Unsupported legacy operations explain the limitation and supported replacement; do not silently drop the entry or invent flags. Keep dynamic syntax in prime/help and semantic guidance in assets. Preserve attribution.

Register all 29 namespaced workflows plus status through one ordinary command transform. The pinned command editor exposes only add/map set; initial `ctx.command.list()` collisions are diagnostic-only, not a reason to withhold a name permanently. S13 supervisor ordering is pre → packages → post, and ConfigCommandPlugin is post: ordinary configuration/file commands replay after package transforms, including config reload, and removing an override restores the package definition. Same-name conflicts with other plugin transforms follow native order; disclose detectable conflicts without promising universal preservation. This is supported host precedence, not broken upstream behavior. Keep public per-rebuild skill `editor.list()` collision checks, but remove the redundant initial skill gate so a removed customization does not permanently suppress registration. Every owned transform checks abort before add and has an owned disposer. Qualify initial/rebuilt/disposed registries using a small ordered-callback fixture, not a host replica or collision manager. Status compares effective public names/descriptions with definitions, reports observable overrides and lookup failures, and discloses that owner identity and identical-description overrides are unobservable; no hardcoded all-command hold survives. Qualify all packaged resource links and external-directory ask/deny from the installed base, reporting unreachable files without bypass. Do not write user files. Native scoped disposers plus setup cleanup remove only owned registrations and abort observers/processes. Shared `beads` skill, user configuration/files, agent names and npm package name remain unchanged.

Opus's resolution review verifies package/config ordering from pinned 2.1.1 `plugin/supervisor.ts:99–103`, `plugin/internal.ts:254–259`, `command.ts:61` and `state.ts:162,178–181`. Its registry suffix-reactivation evidence comes from the unpinned `released` cache, not the exact 2.1.1 cache; do not label that detail pinned or live-qualified. Installed-host discovery, reactivation and permissions remain unexecuted 1.1/6.2 acceptance work. See [the original review](../../../docs/reviews/opus-registration-resolution-review-vuy5.md); its REVISE verdict is historical evidence, not changed by this reconciliation.

### 3. N1 continuity operations and authorization

Use one narrow `src/continuity.ts` module wired from host, backed by `runBd` in `src/prime.ts`. Fixed operations: append task checkpoint (`update <id> --append-notes … --json`), task recovery (`show <id> --json`), memory search/recall and explicit remember with key/content. Do not expose arbitrary argv, shell text, cwd, environment, force, init, sync or admin execution through typed tools. Other workflows retain the ordinary shell tool. Validate operation input and pass argv directly, never construct executable shell strings.

Set each typed definition's `options.permission` to `shell`: S05 filters wholly denied tools before direct/code-mode discovery. At invocation assert `action: "shell"` against canonical resource text for the exact fixed bd operation, `sessionID`, **`agent: context.agent`**, and tool source message/call IDs. Do not substitute the session's default agent. Pass `save: []`, never install a new broad `bd *` grant. S15 makes an "always" response one-call on this path; guidance must explain repeated prompts under ask. Existing project shell `bd *` saved grants may authorize equivalent typed operations, subject to configured denies checked first; this is shell equivalence, not privilege escalation. Qualify these expected outcomes without broadening permissions for convenience. Reject/ask behavior must match the built-in shell for the supported operation, including selective write denials. Preserve rejection as rejection, not successful tool output. Both direct and code-mode paths must filter/check, and the outer code-mode hook must not duplicate a write acknowledgement.

`permission.assert` alone is not shell equivalence: S18 shell preparation also resolves cwd and authorizes external directories before asserting command permissions. Bind execution to the actual invocation session/project directory, never process cwd or a model-supplied path. Apply equivalent `external_directory` assertions for explicit invocation/location access, using invocation identity and no broad saved scope. Recheck that session/location, cancellation and the existing migration guard after approval and before spawning. Use supported config-only `bd context --json` for the guard, rather than `where`'s possible store-opening prefix lookup. The installed Beads CLI owns its normal redirects, worktree discovery, inherited environment, backend/routing and consistency semantics. Normal permissioned CLI equivalence does not promise absolute filesystem or final-store confinement; intended routing after a local miss is not a plugin defect or acceptance blocker. Do not require final-store attestation or a routing-disable switch, clear inherited routing, restrict backend modes, clone metadata/resolvers, or build upstream repair/protective frameworks. Actual OpenCode permission/API incompatibilities still stop the affected path. Minimal host assertion probes belong to 1.1; adapter context/guard/argv fixtures belong to 3.1. Both must pass before N1 activation.

Recheck the guard hold, actual session/location and cancellation immediately before spawning, including after any approval wait. Never let manual-prime advice bypass a hold. Extend existing runner cancellation only as necessary; use finite I/O bounds and abort on stop/unload. A timeout or interrupted write may have landed: disclose uncertainty, re-read on recovery and never blindly retry append/remember. Existing invocation IDs may prevent duplicate handling within the session; no new durable exactly-once system.

Success records actual CLI results and durable references, not merely exit zero. Current marketplace memory source can return `committed:false`, `commit_error` and `commit_indeterminate` after a landed write; preserve those distinctions without automatically committing. Released CLI behavior remains separately qualified. Memory budget refusal is not permission to force or change config. Empty found memory differs from absent memory.

### 4. Context, compaction and lifecycle

M01 awaited context supplies guarded canonical prime and focused recovery cues at the first eligible request and relevant transitions. The model retrieves the current task and relevant memories, interprets failed approaches and chooses meaningful checkpoints. M02 tool hooks preserve results/errors and provide focused cues; adapter acknowledgement invalidates relevant context. External writers require targeted fresh reads on recovery/important transitions; a cache miss is not proof of absence. Preserve distinct local authority when reducing duplicate instructions; retaining a block is preferable to deleting unique policy by marker alone.

M03 compaction is **reference-only**: add acknowledged task/memory references and known unsaved/uncertain status. No persistence, permission waits, flush queue, semantic extraction, recursive same-session prompt or checkpoint wait inside the occupied runner. An awaited hook is not a license to await work from itself. Keep host summary/native-provider compaction intact. Ordinary meaningful checkpoints before compaction provide durability; summary text is not a Beads write.

On 2.1.1, provider replay payloads use `native`; tool execution `state` and UI `metadata` retain their meanings. Preserve host-owned `metadata.keepID` and legacy `metadata.recent`, fork remapping and provider/model replay boundaries. Do not populate hook `result.native.messages`: it replaces summary replay. Do not set a replacement `result` merely to add Beads references, or rename all state/metadata fields mechanically. Fixtures cover retained history, fork recovery and provider/model changes without implementing a compatibility manager.

M04 events use current compaction started/ended/failed lifecycle; retire any assumed `session.compacted` subscription. Events are observations for diagnostics/invalidation/cleanup, never a before-stop barrier or automatic continuation trigger. M05 known-session lookup supplies scope; no dependency on session listing (now released but unnecessary). Scope ephemeral state to actual location/session/audience and discard/re-resolve on move, fork or deletion. M10 disposes registrations, aborts event subscriptions and in-flight processes. Catch non-policy hook errors and report them without indefinite blocking. No final-write or exactly-once crash guarantee.

### 5. Task flow, delegation and extensions

Rewrite the canonical beta guidance in `src/guidance.ts` and agent description, retaining existing agent IDs. Atomic claim and per-bead validation remain required. Exact assignments and single operations stop when done; a previously authorized batch/goal may proceed to another actionable bead within that scope. A newly discovered issue is recorded when authorized but does not expand execution scope. Stop on cancellation, denied authority, scope exhaustion or a blocker requiring a decision. Read-only graph analysis never mutates. Direct work and delegation are chosen for the task, not tool-call counts. Every agent-authored write/claim/heartbeat must carry the actual executor's explicit actor, including typed CLI calls and delegated commands; never fall back to human Git identity. Preserve the invoking host agent for permission evaluation separately from the Beads audit actor: a model-supplied actor must not impersonate another executor, and actor names grant no authority. Use stable executor identity from the authorized invocation/handoff; if unavailable, refuse writes rather than invent an identity. Verify created_by/owner/assignee separately, keep ownership handoffs deliberate and historical authorship unchanged. Repository planning/review tracking follows project-owned AGENTS.md and remains separate from this implementation epic. Optional one-bead mode remains supported; Luna remains explicitly opt-in without model-quality claims; existing step caps remain transparent interruption limits.

Use normal blocking child return (M07) initially, with scope, attempts, evidence, durable references, blockers and next action. Parent reconciles acceptance before closure. NO_TEXT, failed/cancelled child and stale/late result are incomplete outcomes, not success. Do not emit plugin synthetics to restart a stopped parent. Background child completion can wake through host-owned synthetic admission, for which no plugin veto was found; background/nested automation is not selected as a base mechanism. Qualification includes deliberate-stop/late-child races and permission waits. A failed stop guarantee blocks that path; no second poller or job manager.

Engineering dispositions: X01 transport rewriting excluded; X02 terminal evidence retrieval deferred; X03 nested-depth changes deferred, normal children retained; X04 parser changes deferred, host configuration respected; X05 V1/deprecated hooks excluded; X06 native-provider compaction supported; X07 low-level middleware/shell rewriting excluded; X08 use existing diagnostics only, no new storage/RPC/UI service; X09 released paginated listing remains unused; known-session lookup is sufficient. D02/D03/D05 installers/config mutation and D06 guidance-only delivery are not selected. E01 optional one-bead scope, E02 opt-in Luna, E03 guard, E04 permissions/caps, E05 discretionary delegation and E06 targeted freshness implement the accepted base.

### 6. Drift and qualification

Compare both complete source roots (`plugins/beads/`, `internal/templates/skills/beads/`) plus inventory support paths between human-reviewed marketplace-main commits. Resolve default branch to a commit for each comparison; retain both identities and path/diff links. Detect additions/deletions/edits and identifiable renames. A completed comparison exits successfully for both unchanged and changed main content, using informational summary/output only: no drift warning/error annotations, failed product CI or release/adoption gate. Main is development-source evidence, not tagged CLI support. If a change needs an unreleased feature, record explicit deferral until verified inclusion in a supported release; never infer inclusion from dates. Incomplete retrieval/comparison is unavailable evidence, not no change; a distinct collector failure may diagnose it but cannot block the separate product/release gates. Reuse `.github/workflows/beads-contract.yml` scheduled pattern with contents:read only when workflow edits are authorized, keeping the advisory collector independent of stable tagged CLI compatibility tests and their real failures. Repeated main changes remain informational without issue creation or mandatory immediate review. Task 5.1 is independent of N1 qualification. No auto-copy, baseline advancement, version bump or release.

Prepare dependency/types in 1.2 before minimal host probes in 1.1; 3.1 owns adapter fixtures. Live gates 1.1/4.2/6.2 require an isolated disposable host pinned initially to 2.1.1, within `>=2.1.1 <2.2`, with later authority for availability/installation and model access. The installed image CLI is 2.0.29 and stays untouched. Missing live environment blocks live gates/activation acceptance, not source/asset/fixture work.

Admission is intentionally narrower than the historical >=2.0.32 <3 proposal because 2.1 breaks public contracts. Future 2.1 patches are admitted candidates subject to source/acceptance checks, not claimed tested; 2.2+ and 2.0 are outside this redesign’s range. No host version has been live-tested for this redesign.

Qualification has three layers: pinned source checks (completed planning evidence), stub/disposable fixture integration (future task work), and installed-host/model behavior (future acceptance). Exercise the complete installed catalog mechanically and a small representative behavioral set: ordinary ready/claim/validate flow, failed approach and discovered follow-up, task notes versus reusable memory, fresh-session recovery, exact assignment versus authorized continuation, restricted agents, hold/failure and partial child handoff. Record host/CLI/model/provider/reasoning/install path and actual durable outcomes. Repeat only uncertain cases; no write/tool-count quota or exhaustive matrix.

## Risks / Trade-offs

- [N1 privilege differs from shell] → qualify visibility, invocation identity, resources, saved grants and external access before enabling; stop on demonstrated mismatch.
- [Current source differs from released CLI] → use installed help and disposable CLI contracts; preserve both evidence identities and refuse unsupported syntax, never auto-upgrade.
- [Rich guidance is ignored] → behavioral evaluation of recovered meaning, not prompt-string assertions.
- [Collision or late child races defeat guarantees] → targeted fixtures/live checks; fail the affected path explicitly rather than build speculative machinery.

## Migration Plan

The future redesign is opt-in beta/next; stable behavior remains until an explicitly authorized release transition. A later authorized implementation prepares the declared minimum/types within V2 before host qualification, then the package asset list; activation still requires qualification. Before a prerelease compatibility change reaches stable main, release work must settle the stable 1.0.x maintenance branch strategy. This is a release gate, not a source-work blocker or new owner interview; no branch action is authorized here. This assignment changes no dependencies, versions or runtime settings. Exact version/tag/publication remains separate release work. Removal rolls back plugin registrations/assets only, never Beads data or schema. No unresolved owner selections remain; technical acceptance gates are recorded in tasks and the reconciliation record.
