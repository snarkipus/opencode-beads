# Design

## Context

See [proposal.md](proposal.md) for the user problem and [source-evidence.md](source-evidence.md) for pinned native facts. This candidate is grounded in source HEAD `3aba613fcbf0db8c3134d854a04dadcaf45ae54d`, plugin 2.2.1 and native Beads 1.3.4 commit `7ef2fd05eb0cd3bdbde051f93cfc14ccf270cdde`. Source inspection is not runtime qualification.

The inherited `src/host.ts` diagnostics callback supplies observations to the renderer: package/host, registry evidence, typed registration, last request capabilities, context status, a version/context guard result and persistence uncertainty. `src/workflows.ts` captures it once in `ocBeadsWorkflow` v1 metadata, submits the compact command and later expands the snapshot through existing hooks. The model writes the visible answer. `src/context.ts` caches native full prime per session/audience; typed writes invalidate location caches. `src/instructions.ts` reduces only complete marked bodies already contained in attached prime. Skill collisions use the per-rebuild editor and user precedence.

**Independent verdict: CONCUR with the core approach**, incorporating these bounded corrections to the supplied Claude revision:

1. A retained managed body can be customization or additional guidance. It is neither proof of contradiction nor proof of obsolete generation. The marker does not establish which harness created a full-profile block.
2. A missing cache snapshot is an observation, not proof that no eligible request occurred. Describe capture time and available request evidence separately.
3. Code-rendered snapshot content is deterministic for the same observations; asking the model to relay it is not deterministic enforcement. Keep the existing delivery path and disclose this boundary.
4. Store-free native commands can still bootstrap metrics configuration, queue events and detach an uploader; OTel is another export route. A raw allowlist alone does not meet local-only/no-config-change claims. Qualify scoped environment suppression before enabling the new collector.
5. Installed native hook entries can include unrelated hooks; missing can include unreadable or unresolved paths. Render native evidence, not independent verification. A matching witness or shim says nothing about completed maintenance.

These corrections are incorporated here, not deferred to a second concept review. The owner’s adoption-gap and low-effort observations motivate the work; neither a competitor conclusion nor an effort estimate is established.

## Goals / Non-Goals

**Goals:** one useful explicitly requested report, two simple internal collectors, concrete next actions with honest limits, meaningful local instructions/hooks/skills visibility, bounded cache provenance and unchanged authority. Preserve diagnostic collection without store opening and native ownership of normal store operations.

**Non-Goals:** no additional command, schema predictor, witness admission gate, SQL/forensic engine, remote freshness, repair/setup execution, native internals duplication, permanent maintenance ledger, daemon, telemetry feature, rules framework or every-request health scan. No SDK extension or direct UI rendering is required. Do not parse layered OpenCode configuration to infer the configured plugin selector. Do not add support promises, dependencies or a broad native-mode/platform qualification campaign.

## Decisions

### 1. Keep one command and one captured observation

Extract the existing callback’s collection/rendering into a small `src/diagnostics.ts`, with `collectPluginHealth`, `collectBeadsHealth` and a pure renderer. `src/host.ts` supplies current state and native registry lookups; it retains session-location checks and unload cancellation. This is a meaningful shared boundary, not a pluggable check framework. No second public command or typed operation is needed.

The normal report is a fixed Markdown heading, at most one useful failure summary line, and two tables named Plugin and Beads with Check / Status / Value columns. Immediately below the title and before any summary, DATE, VERSION and PATH each occupy their own blank-line-separated paragraph. DATE uses the exact capture timestamp, VERSION the executing manifest name/version, and PATH observed guard.workspace.repoRoot (native cwd_repo_root); absent root is explicitly not observed, without inferring from beads_dir or substituting cwd. Native beads_dir remains in explicit details; metadata is not repeated at the bottom; host and CLI versions appear only in their rows. Native Markdown tables and theme-controlled code styling need no custom TUI renderer; smaller/dim fonts are not promised. Recorded bd version names the advisory witness. Normal output contains no full evidence JSON, routine provisos, limitations/footer prose, unmeasured schema/history/remote rows, default persistence uncertainty, or model-delivery/unique-build/live-qualification notices. Actual unresolved write outcomes remain concise observations. Precise fields such as missing/unreadable/unresolved, partial and not observed preserve the evidence distinctions.

Rows assessed as matching are healthy ✅; observed setup differences that do not block the integration are mismatch ⚠️; known incompatibility or failure that prevents context/tools is unhealthy ❌. Section and overall severity use unhealthy > mismatch > healthy. Neutral unavailable/not-observed/incomplete rows stay visible but contribute neither severity nor heading counts; description clipping is evidence detail only and does not negate assessed membership; no assessed rows render a neutral no-assessed-checks result rather than fabricated healthy. Hook collection failures, unreadable/truncated optional guidance and registry lookup failures are neutral incomplete observations. Unsupported/unavailable CLI, failed workspace/context, confirmed context withholding, packaged-skill failure, command-registration failure and requested-but-unregistered typed tools are unhealthy. Missing/outdated/unidentified native hooks, differing recorded or context CLI versions, duplicate full blocks, detected overrides/missing commands and actual unresolved write outcomes are mismatches. Shims are healthy observed installations; shared-skill absence alone is informational. Witness equality/difference never represents SQL or maintenance completion.

Expose the already-computed command membership-truncation flag separately from combined clipping. Complete membership can support command-presence success even when descriptions were clipped; normal values omit description-cap noise. The existing capture adds definitions.length as expectedCount, allowing measured present/expected counts only for complete membership; old snapshots without that field retain a truthful names-present fallback. Partial membership cannot prove missing membership or complete success. Matching descriptions do not prove ownership or rule out identical-description overrides. No new registry query or qualifier is required.

The existing invocation text is passed to the diagnostics callback. Only text whose trimmed, case-insensitive value equals `details` selects explicit evidence. Exact trimmed case-insensitive `help` selects a static self-contained reference in workflows.ts before the callback, skipping diagnostic collection, file reads and registry probes. Other free text remains literal user input and selects normal output. Static help uses the same v1 capture/replay, and does not suppress the later ordinary prompt lifecycle. Details appends the existing bounded observation/finding payload and useful explanations at capture time, including exact hook entries, provenance, truncation flags and limitations. Root-file and last-request evidence/time stay distinct; absence of request evidence is not zero counts. Short actions appear only when useful, with a concise write effect and check. There is no new administration API or automatic repair.

Keep the compact visible invocation, exact free text, attachments/delivery, v1 snapshot, replay and disposal behavior. The selected report is rendered and captured once. New diagnostic snapshot instructions contain the fully populated report between literal BEGIN_DIAGNOSTIC_REPORT and END_DIAGNOSTIC_REPORT lines, with actual newline bytes before/after markers and a blank-line-separated Original invocation: label before the existing literal invocation text part. Narrow author-facing guidance requests reproduction only of the report, preserving values/labels/order/Markdown and omitting markers, invocation, diagnoses and commentary. There are no placeholders for model reconstruction and no hidden full evidence payload in normal mode. Static help uses the same small framing path. Replay/compaction use the saved snapshot without collection or retrofitting old framing. Generic workflow instructions and old v1 durable snapshots are unchanged. Model guidance does not guarantee byte-exact UI rendering; that limitation belongs in specs/docs and explicit details, not normal report text. Command inventory/descriptions and native authority remain unchanged.

Short rows are Host, Commands, Skill, Typed tools, Context, AGENTS Configured, conditional Write outcomes, bd CLI, Workspace, Recorded bd version and Git hooks. Workspace success says Located. AGENTS Configured means recognized bd full/minimal/Codex markers, not semantic completeness or runtime harness availability: any recognized block is bd block, repeated full blocks are duplicate bd blocks, no marker/file or unreadable/truncated observation is neutral. Raw root-file scope/counts and last-request instrumentation/time stay in details only; no Claude runtime counter is added. Context values preserve existing failed/withheld/lookup-failed severity; missing cached evidence is Not yet loaded, not proof of no earlier eligible request. Skill absence retains existing mismatch classification, packaged load failure remains unhealthy. Hooks count installed entries with overlapping shims as a suffix, retain missing/unreadable/unresolved and call unknown installed identity unrecognized. Recorded bd version states equality/difference only.

Static help explains every row, sources, states, useful remedies/checks and limits without needing packaged docs. docs/diagnostics.md is the thorough repository reference, linked from the docs index, README and user guide; help links its repository URL because docs is not in package files. Preserve all 17 skill resources and 30 commands.

### 2. Preserve a qualified local collection boundary

Only `version`, `context --json` and the added `hooks list --json` are diagnostic native probes. No `--readonly` claim substitutes for path inspection: some native commands open stores before or inside their bodies. No fallback to `where`, `doctor`, upgrade/migration, SQL or prime. Reuse the bounded runner, existing timeout/drain/cancellation and confirmed session directory. Ordinary native full-prime loads and permissioned typed/shell operations remain unchanged.

The no-store statement describes **diagnostic collection**. The existing command submits an ordinary prompt whose normal eligible context lifecycle can load full prime; that separate load can open/migrate a store under native rules. Do not advertise the entire subsequent model request as universally store-free. The package makes this existing delivery distinction explicit for owner acceptance, without adding a diagnostic prime call or suppressing normal prime/memories.

For diagnostic children only, add an optional environment overlay at the existing `src/prime.ts` spawn seam and thread it through the diagnostic guard runner: `BD_DISABLE_METRICS=1`, `BD_DISABLE_EVENT_FLUSH=1`, `OTEL_SDK_DISABLED=true`. The 1.3.4 source supports these separate controls: disabling collection alone can still spawn a prune-only flusher. Do not change shared process/global configuration, user HOME, ordinary context/typed execution environments or SDK settings. Do not use `BD_TEST_MODE` as product policy. Source/helper resolution and exact minimum-version behavior must be qualified in task 1.1 before the new collector is enabled.

This is a response to demonstrated native startup paths, not a hypothetical confinement framework. The original source analysis identified native metrics startup effects, addressed by the accepted diagnostic-only environment overlay and retained qualification. This presentation follow-on reuses those unchanged paths and receipts. If the three controls do not preserve the contract at the supported minimum/baseline, stop the affected collector work for owner disposition. Do not silently relax the guarantee, raise the CLI floor, patch upstream or run deeper commands.

### 3. Small, scoped observations

| Observation | Selected source and implementation seam | Meaning and limits |
| --- | --- | --- |
| Plugin/host identity, registrations, command collisions, capabilities, persistence | Existing `host.ts` state and public command/skill list | Loaded manifest version and admitted host are observable; configured selector, public ownership and identical-description override identity remain unavailable. Retain failed lookup vs empty result. |
| CLI and workspace identity | Extend the existing `guard.ts` success result/probe data with the version it actually saw and selected context fields; do not add checks to admission | Minimum remains 1.3.1; 1.3.4 is a validated baseline, not a maximum. Context config is not store health. Redirection is native-owned. |
| Git hooks | Native list JSON; validate the boundary’s array and required field types | Native uses `core.hooksPath` and common Git directory. Report native scope, without inventing a returned resolved hook path. Missing/unreadable are conflated; installed non-bd hooks and version-agnostic shims need cautious wording. |
| Witness | Bounded read of `.local_version` under **resolved `beads_dir`**, only after usable context | Trim and bound values; present match/differ or absent/unreadable/unsupported. Do not compare SQL state, impose holds, infer chronological history or recommend migration. |
| Managed root instructions | Bounded read of `AGENTS.md` at observed `cwd_repo_root`, otherwise the confirmed session directory labeled as that scope | Count recognized full/minimal/Codex blocks and duplicates; no recursive/global file scan, semantic analysis or unmarked-prose classification. Root-file evidence is separate from request evidence. |
| Request instructions | Extend the existing minimizer result and record counts/time per session when its request hook runs | Reuse exact-body comparison; no new filesystem/process work per request. Record latest seen/replaced/retained counts and unknown before observation, not cumulative pseudo-history. Retained text warrants review only, not contradiction. |
| Shared skill and effective skills | Presence/readability of `.agents/skills/beads/SKILL.md` under the observed project scope; effective registry IDs; per-rebuild collision result | Missing shared skill is informational for other harnesses, not plugin failure. Compare explicit known IDs, not fuzzy content. Effective registration is not use; arbitrary renamed skills are not identified. Reset collision evidence per rebuild. |
| Cache provenance | `context.ts` entry exposes status, successful load time and CLI version observed by its preceding guard; diagnostic read does not call `systemFor` | The version is a preceding observation, not atomic binary attestation. Age/difference signals possible staleness. Typed writes already invalidate; shell/external writes remain unobserved. Separate request observation from cache absence. |
| Remote presence | Optional `sync_remote` presence from supported context output | Store only configured/not reported/unknown; omit raw URL, host credentials, metadata and environment. Freshness for both source Git and Beads is not checked. |

Choose simple read caps (64 KiB for root instructions, 256 bytes for a witness) and explicit truncated/unreadable outcomes; no partial-file freshness conclusions. Shared-skill existence/readability does not require reading its full body. Bound evidence and do not persist raw instructions, prime/memories or context JSON into a diagnostic report. Trust supported native routing; do not implement a path-confinement layer. Missing optional fields produce unknown, while malformed required fields produce failed observation.

A marker hash is generated-template body metadata, not a CLI version or authentication. The first slice reports marker/profile presence but does **not** recompute template hashes or vendor template versions: render options affect the body, and a body/marker mismatch alone does not prove harmful customization. The native AGENTS/CLAUDE reminder only proves separate marked files, not content divergence. Parsing cached prose for that reminder is optional future polish, excluded from required first-slice coverage to avoid another unstable text contract.

### 4. Actions remain explicit recommendations

| Action class | Example | Required wording/verification |
| --- | --- | --- |
| Local inspection | Review reported managed blocks and current effective skill registry; `bd hooks list` | No claim of historical completion; ordinary manual CLI startup can have native telemetry effects. |
| Hook/configuration mutation | `bd hooks install`, with `--beads` or `--shared` only after reviewing the intended layout | Explain hook writes and possible `core.hooksPath` changes; preserve user customization; verify with native listing, which still cannot certify policy freshness. Missing report alone does not prove files absent. |
| Instruction removal/setup mutation | Optional `bd setup opencode --remove`; for an intentionally selected Codex integration, `bd setup codex` | Review local policy before removal. Codex setup refreshes shared skill **and** native hooks/instructions; no skill-only claim. Never recommend `bd setup opencode` installation or `bd init` merely to refresh a skill. |
| Native maintenance review | Prefer pinned release guidance; optionally `bd upgrade review` / `bd info --whats-new` in an independently authorized native workflow | These are not diagnostic probes: ordinary startup can open/migrate the store and consume the one-shot witness. Missing prior-version text is not a new-store diagnosis. |
| Store mutation / synchronization | Release-note operations such as recompute-blocked, migrations, sync, compact/flatten | Excluded from automatic actions. Applicability/completion cannot be inferred here. No sequential SQL chain or inferred repair recommendation; respect applicable native release cautions. |
| Context recovery | Next session or configured idle refresh | Explain normal full-prime behavior and possible native store effects. No forced refresh during diagnostics, no unsupported refresh command. |

Avoid making every note an action. Installed shims do not trigger overdue-maintenance advice. Explanatory action qualifications and unmeasured SQL/history/remote limitations belong in explicit details and documentation; normal output has no default not-measured line.

### 6. Proportionate feasibility and acceptance

The original task 1.1 qualification is retained as completed evidence; this description preserves its original bounded qualification boundary. Use exact 1.3.1 and 1.3.4 disposable local fixtures with isolated HOME/config/cache directories, one initialized repository per version, no configured remote and no operator stores/services. Qualify exact version/context/hook-list argv with the scoped environment, absent hooks then native `--beads` installation as fixture preparation, and capture the actual JSON keys/exits. Deliberate setup/install effects are outside the probe before/after interval. Record file membership/hashes for fixture `.beads`, Git config and isolated HOME/config/cache around probes. A tiny seeded isolated metrics backlog with inherited enabled-export settings exercises suppression; no live external endpoint is needed. Do not call absence of file changes proof of no network: pair execution evidence with the inspected startup/collector/flusher paths and verify actual child env forwarding. A bounded local capture can detect unexpected exports if needed; it does not justify a general network instrumentation framework.

At minimum preserve 1.3.1’s existing context-absence behavior; optional fields may differ. Use mocked malformed JSON, timeout, nonzero and unreadable fixtures for failure branches; do not multiply native modes, semver pairs or schema states. Test the actual registered command → collectors → renderer → captured snapshot path, and prove replay does not recollect and findings never reach admission/context notices. Reuse established permissions/actor/cancellation and lifecycle regressions; new native host requalification is not assumed necessary unless the changed path reveals a specific gap.

## Risks / Trade-offs

- Native preamble effects contradict casual “read-only” assumptions → qualify the scoped environment; preserve the hard no-store/no-config/no-network collector boundary and stop for disposition on a demonstrated mismatch.
- Model response can embellish a deterministic payload → test/render the captured payload, guide faithful relay, document the limit; no promise of deterministic end-user prose.
- Local observations can be mistaken for complete health → precise row names, literal incomplete values, assessed-check severity with visible neutral rows; detailed explanations are opt-in.
- Hook JSON and optional context fields can drift → boundary validation and the existing contract script; no new supported-version range.
- Root-file scope misses nested/global guidance → label scope and complement it with actual request counts; no recursive scanner.
- Additional stored observations can become stale → latest per-session entries only, cleaned on existing forget/location/unload paths; no persistent assessment ledger.

## Migration Plan

No data, schema or user-file migration. After owner acceptance and explicit dispatch, qualify the probes, implement the collector/state/rendering seams, run representative and existing package checks, then return the candidate for parent acceptance. Only a separately authorized owner/parent integration step synchronizes canonical specs and archives the change. Release, version bump, publication and operator rollout are outside this task. Removing the added collector/state in a rollback needs no store cleanup; previously captured snapshots retain their original observations and known historical snapshot-recovery limits.

The selected contract is local-first with suppressed child telemetry and the existing model-mediated delivery. Owner acceptance must explicitly cover these choices and the collector/ordinary-context boundary. If qualification would require weakening that contract, the affected implementation stops; it is not an open license to choose a deeper probe.
