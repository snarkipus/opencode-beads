## Probe and wording details

The no-store command list includes version, context and hooks, and the root hook returns before normal store initialization. It still executes configuration/environment preparation and the legacy-layout guard. Metrics startup precedes that return; the process tail finalizes metrics. This supports **store-free classification**, not blanket nonmutation. `BD_DISABLE_METRICS` has precedence in the metrics enablement resolver. [Root startup and return](https://github.com/gastownhall/beads/blob/7ef2fd05eb0cd3bdbde051f93cfc14ccf270cdde/cmd/bd/main.go#L1049), [metrics resolver](https://github.com/gastownhall/beads/blob/7ef2fd05eb0cd3bdbde051f93cfc14ccf270cdde/cmd/bd/main.go#L2452).

`BD_DISABLE_EVENT_FLUSH=1` suppresses the detached flusher; this matters even when collection is disabled because a prior queue could otherwise be pruned. `OTEL_SDK_DISABLED=true` overrides both modern and legacy OTel selectors. The child overlay is proposed only for diagnostics; it neither changes user settings nor claims to suppress ordinary native operations. [Flusher environment gate](https://github.com/gastownhall/beads/blob/7ef2fd05eb0cd3bdbde051f93cfc14ccf270cdde/internal/metrics/spawn.go#L45), [OTel enablement](https://github.com/gastownhall/beads/blob/7ef2fd05eb0cd3bdbde051f93cfc14ccf270cdde/internal/telemetry/telemetry.go#L83).

`HookStatus` uses exported, untagged `Name`, `Installed`, `Version`, `IsShim`, `Outdated` fields and list emits a `hooks` array. JSON names follow that producer; exact runtime keys/envelope and version differences still need the disposable contract check. Directory resolution failure and unreadable hook files report not installed. A readable non-Beads hook can report installed without a version; JSON omits the internal `IsBdHook`. Thin/section shims are never marked outdated by this check. This does not certify the latest wrapper policy. [Hook producer and classifier](https://github.com/gastownhall/beads/blob/7ef2fd05eb0cd3bdbde051f93cfc14ccf270cdde/cmd/bd/hooks.go#L500).

The local version witness is best-effort file state, updated independently of successful native reconciliation. Previous version is held in process memory only for detected upgrades, not all differences; later matching calls cannot reconstruct an upgrade history. Missing, older, newer and matching values therefore cannot diagnose schema state or completion. [Version tracking](https://github.com/gastownhall/beads/blob/7ef2fd05eb0cd3bdbde051f93cfc14ccf270cdde/cmd/bd/version_tracking.go#L45).

Native upgrade guidance recommends hook refresh. The supplied Snark Surface release-note transcript describes maintenance applicability, including recompute-blocked for affected migration-0059 history and cautions on compact/flatten for applicable migration-0062 clones. Those are not evidence that a particular workspace has completed or still needs that maintenance. Diagnostics offers release guidance, not a locally reconstructed migration inventory. [Pinned upgrading guide](https://github.com/gastownhall/beads/blob/7ef2fd05eb0cd3bdbde051f93cfc14ccf270cdde/docs/getting-started/upgrading.md).

## Local product seams and preserved contracts

- `src/host.ts`: current diagnostics callback, session-location checks, registries, request observations, invalidation and disposal.
- `src/guard.ts`: minimum 1.3.1, version/config-only context probes, absence/protocol distinction; no witness admission.
- `src/context.ts`: per-session/audience full-prime cache and status; no persistent plugin database.
- `src/instructions.ts`: full/Codex marker matching and complete-body duplication rule; retained text is preserved intentionally.
- `src/workflows.ts`: one ordinary prompt, compact visible text and captured `ocBeadsWorkflow` v1 instructions; model relay is not code-rendered UI.
- `src/prime.ts`: bounded native runner currently inherits environment and has no diagnostic-only overlay.
- `tests/host.test.ts`, `tests/workflows.test.ts`, `tests/context.test.ts`, `tests/instructions.test.ts`, `tests/guard.test.ts` and `scripts/bd-contract.ts`: existing dispatch, replay, scope and native-contract seams to extend, not replace with duplicated test logic.

Only `workflow-access` needs a delta. Its full modified diagnostics requirement preserves every old scenario. Native store ownership, coherent authority, capability-aware guidance, compact workflow history and the known historical snapshot-recovery deficiency remain controlling. The planning report records strict validation separately from this source rationale.
